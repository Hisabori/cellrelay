# CellRelay 0.8 — 아이폰 셀룰러 중계 실험

게임 모드: GAME-MODE.txt에 따라 공식 터널 엔진을 별도 준비한 뒤 앱을 관리자 권한으로 실행합니다. 지포스 나우 지원은 실험 단계이며 PC 전체 TCP·UDP와 DNS 경로에 영향을 줍니다. 아이폰 앱은 0.7을 계속 사용합니다.

간편 연결: CR1 코드 또는 QR 이미지를 등록한 뒤 '코드 적용 · 검사 · 간편 연결'을 누르면 HTTPS 검사 후 PC 프록시를 시작합니다. 브라우저 프록시는 화면의 로컬 주소로 설정하세요.

QR 등록: 아이폰에서 'PC 등록용 QR 보기'를 누르고 화면을 캡처하여 본인 PC로 전달합니다. PC에서 'QR 이미지로 등록'으로 열거나 이미지를 복사하고 '클립보드 QR 등록'을 누릅니다. QR에는 연결 키가 포함됩니다. 카메라 스캔은 포함하지 않습니다.

UDP · QUIC 전달 탭: 목적지 호스트와 UDP 포트, PC 로컬 수신 포트를 입력합니다. 앱에서 로컬 포트로 보낸 UDP 패킷을 아이폰의 셀룰러로 전달합니다. QUIC 클라이언트는 원래 서버 이름과 인증서 검증을 유지한 채 목적지 주소만 바꿀 수 있어야 합니다. 네이티브 QUIC 터널이나 브라우저 자동 HTTP/3 전환은 구현하지 않았습니다. TCP 터널의 재전송 대기 때문에 지연이 증가할 수 있습니다. UDP 지원에는 0.7 IPA가 필요합니다.

Windows HTTP/HTTPS 프록시 → 로컬 TCP 연결 → 아이폰 앱 → 셀룰러 TCP 연결.
아이폰의 출구는 Network.framework의 `requiredInterfaceType = .cellular`로 제한합니다. 셀룰러 경로가 없으면 연결 실패하며 PC에서 직접 인터넷으로 우회하지 않습니다.

**이 버전은 통신사 공유 데이터 미차감을 입증한 제품이 아닙니다.** Android Tetrd에서 확인한 결과를 iOS에서 확인한 것으로 취급하지 않습니다. 프로토콜은 자체 구현이며 Tetrd와 호환되지 않습니다.

## 제공 파일과 검증 상태

- `Desktop/CellRelay.exe`: .NET 포함 Windows x64 실행 파일.
- `windows/`: Windows GUI 및 HTTP/CONNECT 중계 소스.
- `ios/`: SwiftUI 아이폰 앱 소스, XcodeGen 프로젝트 정의, macOS 빌드 스크립트.
- Windows 자체 시험: 모의 아이폰 서버로 CONNECT 바이트 왕복, HTTP 요청 주소 변환, 인증 거절 후 다음 요청 복구, 업로드·반닫힘 응답, 유휴/중지 정리, 연결 32개 제한과 같은 포트 재시작. 잘못된 요청·모호한 본문 길이·IPv6 목적지 파싱도 검사합니다.
- iOS 0.4: macOS CI 컴파일 및 미서명 IPA 패키지 검사가 통과했습니다. 미검증: 서명/설치, 실제 아이폰의 로컬 연결 수신 및 셀룰러 출구, USB 경로, 통신사 차감, 장시간 안정성과 백그라운드 유지 시간.

## 아이폰 빌드 및 설치

1. Mac에 Xcode와 XcodeGen을 준비합니다 (`brew install xcodegen`).
2. 터미널에서 `ios` 폴더로 이동하여 `bash Build-iOS.sh`를 실행합니다.
3. Xcode에서 생성된 `CellRelay.xcodeproj`를 열고 Signing & Capabilities에서 본인 Team을 선택합니다. 필요하면 Bundle Identifier를 고유하게 변경합니다.
4. 아이폰을 선택하여 Run으로 설치합니다. 개발자 모드/신뢰 승인이 필요할 수 있습니다.
5. 스크립트가 생성하는 `CellRelay-unsigned.ipa`는 미서명이며 설치 전 재서명이 필요합니다. 빌드 스크립트 실행 성공 전에는 IPA 제공 완료로 간주하지 마세요.

## 연결

1. 아이폰의 셀룰러 데이터를 켜고 PC와 아이폰 사이의 로컬 연결을 준비합니다. 개인용 핫스팟의 Wi-Fi 또는 USB 네트워크를 실험할 수 있지만, iOS 버전/드라이버에 따라 앱 리스너 접근이 가능한지는 실제로 확인해야 합니다. USB 자체 프로토콜/usbmux 터널은 구현하지 않았습니다.
2. 아이폰에서 CellRelay를 열고 **중계 시작**, 로컬 네트워크 접근을 허용합니다. 화면에 표시된 로컬 주소와 연결 키를 확인합니다. PC에서 도달 가능한 아이폰 주소가 필요합니다. Windows 기본값 `172.20.10.1`은 예시입니다.
3. 압축을 풀고 `Start.cmd`를 실행합니다. 아이폰의 연결 정보를 복사해 적용하거나 주소·키·'실제 중계 포트'를 직접 입력합니다. 기본 포트는 49152지만 충돌 시 바뀔 수 있으므로 앱에 표시된 값을 사용하세요. 실행 시 `.runtime`에 포함된 런타임을 풉니다.
4. Windows의 **아이폰 연결 검사**로 인증과 아이폰의 example.com:443 TCP 접속을 시험할 수 있습니다. 이 버튼은 소량의 실제 셀룰러 통신을 발생시킬 수 있으며 공유 데이터 차감 여부는 검사하지 않습니다. 테스트 브라우저의 HTTP 프록시와 HTTPS 프록시를 `127.0.0.1:8877`로 설정합니다. Firefox의 수동 프록시 설정을 쓰면 브라우저만 대상으로 시험할 수 있습니다. 프로그램은 Windows 시스템 프록시나 네트워크 설정을 변경하지 않습니다.
5. 작은 HTTPS 페이지를 열고 Windows 및 아이폰 로그에 목적지와 셀룰러 연결이 표시되는지 확인합니다. 앱을 중지했을 때 요청이 실패하는지도 확인하여 직접 접속 여부를 점검합니다.
6. 시험 후 브라우저 프록시 설정을 원래대로 복구합니다.

아이폰 0.4는 화면 전환 시 iOS가 허용한 시간 동안 기존 연결을 마무리하며 새 연결은 거절합니다. 시간 만료 또는 기존 연결 완료 시 중지하고 앱 복귀 시 설정에 따라 재개합니다. 상세 조건은 BACKGROUND.md를 참고하세요. 백그라운드 상시 서비스, VPN/TUN 전체 PC 트래픽, UDP/QUIC, 게임·음성 통신, 자동 USB 검색, 재접속 시 기존 세션 복구는 제공하지 않습니다. HTTPS는 CONNECT로 원본 TLS를 유지하며 인증서를 설치하거나 복호화하지 않습니다.

## 0.4 PC UI와 백그라운드

0.4.2는 아이폰에서 49152 포트가 사용 중일 때 OS가 배정한 빈 포트로 다시 시작합니다. 화면의 '실제 중계 포트'와 CR1 연결 정보에 선택한 포트를 반영합니다. 아이폰 앱을 재시작한 뒤 연결 정보를 다시 복사해 새 PC UI에 적용하세요. PC에도 '아이폰 실제 중계 포트'를 직접 입력할 수 있습니다. 구 PC 버전은 가변 아이폰 포트를 지원하지 않을 수 있으므로 함께 업데이트하세요.

PC 쪽도 요청한 프록시 포트가 사용 중이거나 Windows 예약 포트이면 다른 포트를 바인딩합니다. 빨간색으로 표시된 PC 주소를 브라우저 프록시에도 입력해야 합니다. 구버전 프로세스를 종료하거나 점유 포트를 빼앗지 않습니다. 새 UI 중복 실행은 막습니다. 아이폰 포트와 PC 프록시 포트는 서로 다른 값입니다.

Windows에 연결 순서·마지막 검사 시각·사용 안내 탭을 추가했습니다. 아이폰에서는 기존 연결 마무리용 백그라운드 시간 요청과 복귀 시 자동 재개를 추가했습니다. 무기한 실행이나 특정 유지 시간을 보장하지 않습니다. 잠금·백그라운드·만료 동작은 실제 기기에서 별도 확인해야 합니다.

## 0.3 연결·진단 기능

- 아이폰 소스에 주소별 **연결 정보 복사** 버튼을 추가했습니다. 중계를 시작한 후 PC에서 사용할 주소를 골라 복사하고, Windows 맨 위 입력란에 붙여 넣은 뒤 **연결 정보 적용**을 누릅니다. 적용은 주소·연결 키 입력만 수행하며 중계 시작은 별도로 누릅니다. iOS 컴파일 및 실제 기기 간 전달은 아직 검증하지 않았습니다.
- 연결 코드는 `CR1:` 다음에 JSON을 Base64로 인코딩한 형식입니다. 암호화가 아니며 인증 키가 포함되므로 타인에게 공유하지 마세요. 기존 주소·키 직접 입력 방식도 유지합니다.
- PC 프록시 포트는 1024~65535에서 선택할 수 있습니다. 브라우저에도 같은 포트를 설정하세요. **프록시 주소 복사**로 현재 주소를 복사할 수 있습니다. 사용 중인 포트이면 시작 오류를 표시합니다.
- 중계 시작 성공 시 아이폰 주소와 PC 프록시 포트를 `%LOCALAPPDATA%\CellRelay\settings.json`에 기억합니다. 연결 키와 연결 코드는 저장하지 않습니다. 손상된 설정은 기본값으로 복구합니다.
- 전송량 외에 약 1초 간격 전송 속도를 표시하고, 연결 검사는 아이폰 인증·목적지 TCP 접속까지 걸린 시간을 표시합니다. 인터넷 왕복 지연이나 속도 측정 결과는 아닙니다.
- **진단 기록 저장**으로 현재 통계와 화면의 기록을 텍스트로 저장합니다. 현재 연결 키·CR1 연결 코드는 가리지만 목적지 호스트는 남을 수 있으므로 공유 전 확인하세요. **기록 지우기**는 화면의 기록을 비웁니다.
- 새 연결 코드 파싱·오류 거절·설정 저장 및 손상 복구·진단 키 가림 시험을 추가했습니다.

## 0.2 안정화 변경 내역

- Windows 및 아이폰 앱 소스에 활성 연결·업로드·다운로드 표시. 통신사 과금량이 아니라 앱이 중계한 바이트 수입니다. Windows는 HTTP 요청 헤더를 포함하고, 양쪽 프로토콜 제어 메시지는 제외합니다.
- Windows 연결 검사, 32자리 연결 키·주소 검증, 로그 크기 제한, 닫는 중 발생하는 화면 갱신 예외 처리.
- 인증/목적지 연결은 Windows 20초, 아이폰 소스는 약 20~25초로 제한합니다. 중계 중 2분간 양방향 활동이 없으면 연결을 정리합니다. 아이폰의 유휴 감시는 5초 간격입니다.
- 잘못된 요청에는 400, 과도한 헤더에는 431, 연결 실패에는 502, 연결 대기 시간 초과에는 504를 반환합니다. 터널이 이미 열린 뒤 오류가 생기면 텍스트 오류를 끼워 넣지 않고 연결을 닫습니다.
- 중복 Content-Length, Content-Length/Transfer-Encoding 동시 지정, 잘못된 CONNECT 목적지 거절. 연결 전용 헤더 및 인증 헤더를 목적지 전달에서 제거합니다.
- 한 요청 실패 후 다음 요청은 새 연결로 시도합니다. 진행 중인 업로드나 기존 연결은 자동 재전송하지 않습니다.
- 아이폰 소스: 실행 세대 식별자로 이전 리스너의 늦은 콜백을 무시하고, 큐 순서대로 세션을 정리합니다. 연결 키 복사·수동 재발급 추가. 이 변경은 아직 macOS/iOS에서 컴파일하거나 기기로 검증하지 않았습니다.

## 공유 데이터 검증 절차

1. 통신사 앱에서 일반 데이터와 공유 데이터 잔량, 측정 시각을 함께 기록합니다.
2. PC 업데이트·클라우드 동기화 등 다른 트래픽을 멈추고 테스트 브라우저만 프록시로 연결합니다. 다른 PC 앱은 프록시를 사용하지 않을 수 있습니다.
3. 작은 크기의 알려진 파일로 먼저 중계 작동을 확인합니다. 일반 셀룰러 잔량은 줄어들 수 있습니다.
4. 통신사 집계 반영 시간을 기다린 후 두 잔량을 다시 기록합니다. 같은 조건에서 반복하고, 아이폰 모델/iOS/통신사/요금제/연결 방식도 함께 적습니다.
5. 공유 데이터가 줄면 해당 조건에서는 요구사항 실패입니다. 미차감 결과도 시험한 조건에만 적용합니다. 아이폰 중계 연결 로그만으로 차감 결과를 판정하지 마세요.

## 연결 보안과 한계

PC 프록시는 로컬 루프백에만 열리며 최대 32개 연결을 처리합니다. 아이폰 앱은 네트워크 인터페이스에서 수신하며 시작 시 표시되는 임의의 128비트 연결 키가 있어야 중계합니다. 앱 재실행 시 키가 바뀝니다. **로컬 연결의 키와 HTTP 평문은 암호화되지 않으므로 신뢰하는 USB/개인 로컬 네트워크에서만 시험하세요.** 연결 키를 공개하지 마세요. 인터넷에 아이폰 포트를 노출하지 마세요. 공용 서비스 제공에 필요한 TLS 페어링, 사용자 계정, 과금, 원격 운영 기능은 포함하지 않았습니다.
